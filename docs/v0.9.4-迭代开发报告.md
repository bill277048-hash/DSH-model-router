### 2.2 阶段 A —— match 收紧密 + 漏洞 1/2 修复

| 步骤 | 落点 | 实现 |
|---|---|---|
| A-1 | lib/config.js | 导出 `isPlainObject`；新增 `stripLegacyMatch(rules, allowLegacyMatch, log)` helper（false 时复制 rules 并剔除 match + warn；true 时原样返回） |
| A-2 | lib/config.js | `normalizeConfig(raw, {log})`：入口先 strip（M-1/决策 7），`merged.allowLegacyMatch`；match 明细解析仅 legacy 分支可达；类型 fail-fast 保留、开关无关 |
| A-3 | lib/index.js | store 加载点改 `cfg.rules = stripLegacyMatch(stored.rules, cfg.allowLegacyMatch, log)`（漏洞 1 根治点）；`normalizeConfig(config, { log })` |
| A-4 | lib/config.js + lib/routes.js | `normalizeState(raw, legacyMatch)` 复用 patch 现值；routes POST /state 透传 `config.allowLegacyMatch === true`（漏洞 2）；不传 opts.log（S-3：面板保存无 match-warning） |
| A-5 | lib/routes.js | status `config` 块回显 `allowLegacyMatch` |

### 2.6 阶段 D —— 每日报告 UX 三连修（v0.9.3 实机补强）

**触发**：用户反馈 v0.9.3 实机部署后点击「立即生成昨日报告」无效或不知落盘位置。代码定位确认 3 个 UX 缺陷（R-1/R-2/R-3）。

| 项 | 落点 | 实现 |
|---|---|---|
| R-1 修 | lib/daily.js | `readDayRecords(day)` 内存权威 + 磁盘追加事实——先吃 `_buffer[day]`（引用相等去重），再吃 NDJSON 文件行；`hasData` 同样受惠 |
| R-2 修 | lib/daily.js | `generate(day)` 写盘失败 throw 而非吞错；包装错误含 `daily report write <day> failed: <cause>` |
| R-2 路由 | lib/routes.js | `POST /reports/generate` 显式 try/catch → 500 + `error: "report write failed: ..."`，不被通用 guard 包成模糊提示 |
| R-3 修 | lib/routes.js | `/api/model-router/status` 顶层新增 `reports: { enabled, reportDir, hour }`；enabled=false 也回显，path=null |

### 2.7 阶段 E —— 每日报告启动按钮 + 生成反馈 toast（UX 补丁）

**触发**：用户追问「不知道在哪儿开 reports.enabled」+「点击生成无提示」。阶段 D 修了后端数据链路，但「开启入口」与「操作反馈」仍是 UX 空白。

| 步骤 | 落点 | 实现 |
|---|---|---|
| E-1 | lib/config.js | `normalizeState` 透传 `reports` 段（未提交时不重置 patch 现值；显式提交才规范化 + 回传）；`reports.hour` 沿用既有 HH:MM 校验 |
| E-2 | lib/routes.js | POST `/state` 探测 reports 切换：`reportsChanged` → 响应带 `requiresReload: true` + `reloadHint`（明示需重启 dsh 让 daily 实例装配，macOS 命令随附）；`config.reports` 引用同步替换 |
| E-3 | client.js | 「每日报告」页签未启用时显示横幅 + 「一键启用每日报告」按钮（POST `/state` 提交 `{reports:{enabled:true, hour}}`）；已启用态顶部显示 reportDir + 自动生成时刻；「立即生成」按钮在未启用时置灰（title 提示先启用） |
| E-4 | client.js | 全局浮层 toast（sticky 底部）：生成成功显示「已生成 <day> · 调用 N 次 + 文件路径」；失败显示原因；「reports disabled」类错误内嵌「立即启用」按钮；3.5s/6s 自动消失；组件卸载清理计时器 |

## 四、中间的疏漏与修复

### 疏漏 1（最严重）· v0.9.4 A/B 单测用例实际缺失
- **现象**：会话摘要声称「已添加 v0.9.4 A/B 单测用例（throttleWait 三态、contextReorder 前移等）」，但恢复会话后以 `grep "test('v0.9.4"` 复核，测试文件中**没有任何 v0.9.4 前缀用例**——仅有 `allowLegacyMatch: true` 辅助改动与注释。
- **影响**：若直接宣称完成，A/B 工作流的验收（A2~A7、B-A1、B-B1/B-B2/O-2、B-B3）将无单测证据支撑。
- **处理**：按计划附录三补齐 14 项（A 9 + B 5），全部通过。
- **教训**：以「摘要/记忆」代替「文件证据」会掩盖未落地；本报告所有结论均以 `grep`/运行日志/文件内容为证。

### 疏漏 2 · 测试进程挂起（v0.9.3 遗留，复验才暴露）
- **现象**：90 项测试全部通过后 `node --test` 进程不退出，现场残留 4 个历史挂起的后台测试进程（12:00–12:30 启动，均超时被杀）。
- **根因**：`lib/daily.js` DailyLedger 构造函数 `setInterval` 兜底 flush 计时器未 `unref()`，保持事件循环存活。
- **处理**：`this._flushTimer.unref?.()`（后台兜底计时器不应阻塞进程退出；宿主 dsh 长驻保活，单测自然退出）；清理全部挂起进程。
- **教训**：此前「测试全绿」的判定可能建立在进程被超时终止而非正常退出的基础上，属于复验盲区。

### 疏漏 3 · modes 过时断言
- **现象**：`modes v0.7.0` 测试断言 `VALID_MODES` 为 `['balanced','fast','stable']`，漏了后续版本新增的 `custom` / `free-tier`。
- **处理**：更新为 5 模式集合。
- **教训**：模式/枚举类断言未随功能演进同步，属增量开发中的常见遗漏。

### 疏漏 4 · 计划文档测试基数口径偏差
- **现象**：计划 §3.0 单测核算「现有 52 + 新增 14-17 ≈ 67-69」，实际测试文件基线为 **90** 项（v0.9.3 后持续累积）。
- **影响**：仅影响预估口径，不影响验收（V1 以实际 104/104 为准）。
- **处理**：报告与变更摘要按实际 104 项口径记录。

### 疏漏 5 · 计划附录 diff 行号与最终代码偏移
- **现象**：附录一/二的行号（如 config.js L334-371、wrapper.js L469/L543）基于 v0.9.3 实机坐标，实现时按函数语义定位，部分行号偏移。
- **处理**：实现以语义为准；本报告以函数/文件为锚点描述，不依赖行号。
- **教训**：行号级坐标在文档迭代间易失效，宜以符号/函数名为准。

### 疏漏 6 · 历史挂起进程未受控
- **现象**：4 个僵尸后台测试进程占用资源（曾误判为「运行中」）。
- **处理**：统一 `pkill` 清理后全量重跑，避免旧进程输出污染判定。
