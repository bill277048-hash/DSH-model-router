> ⚠ **本节初稿曾写「8 处」——那是错的**。原因是首轮用了单行正则
> `catch\s*\([^)]*\)\s*\{\s*\}`，只能匹配 `} catch { }` 写在一行的情况；
> 实际绝大多数是**多行**（`catch {` → 注释 → `}`）。改用「块内是否仅含注释」
> 的检测后得 **35 处**。**教训**：扫源码结构不要用单行正则。

## 八、复核过程的方法论教训（已入 skill §G）

本次复核在**批量跨文件突变**上踩了 4 个坑，且**互相叠加**，一度表现为
「测试本身不稳」的假象（看到 53 条红）：

1. **备份路径拼接错**：`basename $file .js` 已剥后缀，又拼回 `.js` → 备份名错乱
2. **突变脚本 `process.exit(1)` 跳过了还原** → 文件停在上一轮的突变态，下一组再叠一层
3. **用 pass/fail 数代替「文件是否还原」的判断** → 两组突变互相抵消时也可能「全绿」
   - **唯一可信判据**：`git diff HEAD -- <file>` 为空
4. **SIGTERM 后没做「污染盘查」就继续** → 累计红数被误读为测试问题

**收敛做法**：跨文件批量突变 → **一次一组、每组前后各验一次 `git diff`**，宁慢勿乱。
