> ⚠️ **C-08 的环境前置条件**（2026-09-26 实测踩到，原用例文档未写）
>
> 若**已有跑批在进行中**，`POST /model-test` 会**先**返回 **409 `model-test already running`**，
> **不会**走到「空 targets」的 400 校验 —— 于是 C-08 被**误判为 FAIL**。
>
> 实测复现：实机冒烟从 **14/14 掉到 13/14**，失败项正是 C-08，返回
> `409 model-test already running（DELETE 中止或等待完成）`；
> 执行 `curl -X DELETE 127.0.0.1:3081/api/model-router/model-test` 中止后，
> 立即恢复 **400**，冒烟回到 **14/14**。
>
> **结论**：这是**测试环境状态**问题，**不是产品缺陷**。
>
> **执行前置**：先确认无跑批在跑。**探测方式**（2026-09-26 修正）：
>
> ```bash
> # ✅ 正确：直接探 C-08 本身。期望 400；若得 409 则说明有跑批在跑
> curl -s -X POST 127.0.0.1:3081/api/model-router/model-test \
>      -H 'content-type: application/json' -d '{"targets":[]}' -w ' → %{http_code}\n'
>
> # ❌ 错误：不要用 DELETE 的返回值判断 —— 实测它**无条件返回 200**
> #    （`{"ok":true,"message":"已请求中止…"}`），无论有无跑批在跑，
> #    故它**不能**作为「是否有跑批」的判据。
> ```
>
> **若有跑批在跑**：先 `DELETE` 中止 → 等约 8 秒 → 用上面的 POST 复探，得到 400 再开测。

## 五、验证闭环

> **闭环的三个层级** —— 下面 5.1 讲的是「单个用例」的闭环（L1）；
> 但**单点全绿不等于产品可用**，还需 L2 链路闭环与 L3 端到端闭环。

| 层级 | 定义 | 判据 | 涉及用例 |
| --- | --- | --- | --- |
| **L1 单点闭环** | 一个用例走完「入口 → 动作 → 观测 → 判定」| 四要素齐全（见 §5.1）| 全部 60 例 |
| **L2 链路闭环** | 把「配置 → 生效 → 落盘 → 读回」串成链 | **任一环断裂即整链 FAIL**（不允许「部分通过」）| 见下表 |
| **L3 端到端闭环** | 一次**真实对话**贯穿全流程 | 用户侧**无感知** + 各观测面一致 | E-04 · E-05 · A-06 · B-04 · F-06 |

**L2 四条链路**

| 链路 | 环节 | 用例 |
| --- | --- | --- |
| **配置链** | 面板输入 → `/state` 校验 → 写 `state.json` → 重启 → 读回 | A-05 · C-01~C-03 · E-03 · C-10 · F-05 |
| **报告链** | 对话记账 → 日账本 NDJSON → 生成报告 → 面板渲染 | A-06 · A-07 · B-06 · F-06 |
| **档案链** | 跑批 → 落盘 → 列表 → 详情 → 排序 | B-08 · F-06 · D-08 |
| **切换链** | 首选失败 → 进 cooldown → 换候选 → 记账 → 诊断可见 | E-04 · E-05 · B-04 · A-06 |

**L3 是本计划唯一的「产品级」判据** —— 即使 L1 全部 PASS，
只要 L3 失败（用户感知到了切换 / 对话中断），**产品仍不可发布**。

### 5.1 每个测试项的闭环路径
