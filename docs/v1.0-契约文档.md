## 〇、契约稳定性分级

本文档为每项契约标注稳定性。**升级承诺**：

| 标记 | 含义 | 变更承诺 |
| --- | --- | --- |
| 🟢 **稳定** | v0.9.0 之前即存在、形态未变 | 破坏性变更须升主版本 |
| 🟡 **实验** | v0.9.x 阶段新增 | 可能在小版本内调整；**依赖前请确认版本** |

> **为什么有「实验」**：阶段 A（v0.9.9–v0.9.23）为快速迭代期，新增能力（档案、时段、
> 声明通道）的字段仍在收敛。阶段 B 的目标是把它们**逐步转为稳定**。

# 一、API 端点契约

**基础路径**：`/api/model-router`（`statusPath` 可配置，默认 `/api/model-router/status`）
**回环围栏**：所有端点仅接受**本机回环**请求（socket 回环 + Host 回环 + 浏览器同源）。
`X-Forwarded-For` **永不可信**。违反 → `403`。

## 1.2 逐端点契约

### 1. `/status` — 插件状态快照 🟢

- **方法**：GET（其他方法 → `405`）
- **参数**：无
- **200 响应**（顶层键）：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | boolean | 恒 `true` |
| `plugin` | string | 恒 `'@botton/dsh-model-router'` |
| `version` | string | 读 `package.json`（**不硬编码**）|
| `uptimeSec` | number | 插件运行秒数 |
| `checkedAt` | string | ISO 时间戳 |
| `config` | object | **当前生效配置**（见 §二）|
| `registry` | object\|null | `registry.snapshotOut()`：provider 目录镜像（含 `settingsNs`）|
| `probe` / `quota` / `metrics` / `cooldown` | object | 各子系统快照 |
| `wrapperStats` | object | wrapper 计数（`wraps`/`failovers`/`timeouts`/…）|
| `reports` | object | 日账本状态（`enabled`/`reportDir`/…）|
| `modelTest` | object | model-test 运行快照 |
| `timeWindows` | object\|null | 段回显：`{segment, nextBoundaryAt, peakStart, valleyStart, …}` |

- **安全**：**不含任何凭据材料**（有测试守住，见 `test/unit.test.mjs` §v0.9.24 #7）

### 2. `/state` — 保存配置 🟢

- **方法**：POST（其他 → `405`）
- **请求体**：config patch（同 §二 schema）
- **200 响应**：`{ ok, message, ...归一化后的 config }`
  - `message` 三种：「已保存并即时生效」/「已即时生效，但持久化失败（重启后回落 patch config）」/「已保存到 patch，但需重启 dsh 让 daily 实例生效」
- **400**：`请求体须为合法 JSON` / 配置校验失败（`error` 带具体原因）
- **500**：持久化失败

### 3. `/quota/windows` — 查窗口限额 🟢

- **方法**：GET
- **参数**：`?provider=<name>`（**必填**）
- **400**：`missing ?provider=`
- **200 响应**：`{ ok, provider, ...snap }`，`snap` 形如
  `{ undeclared: true, fiveHour: null, weekly: null, customWindows: [] }`

### 4. `/quota/reset` — 重置窗口 🟢

- **方法**：POST
- **请求体**：`{ provider, windowId }`（均必填）
- **400**：`missing provider / windowId`，或 `{ok:false, error}`
- **200 响应**：`{ ok, provider, windowId, used, resetAt }`

### 5. `/quota/sync` — 同步窗口声明 🟢

- **方法**：POST
- **请求体**：`{ provider, windows, customWindows }`
- **400**：`missing provider` / 校验失败
- **200 响应**：`{ ok, provider, windows, customWindows, message }`（持久化失败时 `ok:false` + `500`）

### 6. `/probe` — 触发 API 健康探测 🟢

- **方法**：POST
- **200**：`{ ok: true, result }`　**202**：已触发（异步）　**500**：`probe failed: …`

### 7. `/benchmark` — 触发基准测试 🟢

- **方法**：POST
- **200**：`{ ok: true, report }`　**400**：入参非法　**500**：`benchmark failed: …`

### 8. `/reports` — 读每日报告 🟢

- **方法**：GET
- **参数**：`?l1=1`（返回 L1 摘要）/ `?day=YYYY-MM-DD`
- **200**（单日）：`{ ok, report: { ok, day, generatedAt, ...report }, generated, markdown }`
- **200**（L1）：`{ ok, days, today }`
- **404**：该日无报告　**503**：`reports` 未启用

### 9. `/reports/generate` — 生成每日报告 🟢

- **方法**：POST
- **200**：`{ ok, report, generated, markdown, day }`
- **404 / 500 / 503**：同 `/reports`

### 10. `/loadtest` — 负载测试 🟡

- **GET** → `{ ok, ...loadtest.snapshot() }`
- **POST** → `202`（异步启动）／`409`（已在跑）／`400`（入参非法）
- **DELETE** → `{ ok, message: '已请求中止（当前请求完成后停止调度新请求）' }`
- **503**：未装配

### 11. `/model-test` — 模型全自动测试 🟡

- **GET** → `{ ok, running, aborted, last, list, reportDir }`
  - ⚠ **v0.9.23 变更**：不再要求 `reports.enabled`（原为 `503`），判据改为 `modelTest.reportDir` 可用
- **POST** → `202`（异步）／`409`（已在跑）／`400`（`targets`/`phases` 非法）
- **DELETE** → `{ ok, message: '已请求中止…' }`
- **503**：`model-test 未装配或档案目录不可用`

### 12. `/model-test/manual` — 人工校正档案 🟡

- **方法**：POST
- **请求体**：`{ runId, targetKey, manualTpm?, manualMaxContext?, label?, notes? }`
- **200**：`{ ok, targetKey, warnings }`
- **400**：入参非法 / **路径越界**（`runId` 含 `..` 或非法字符）
- **404**：档案或 target 不存在　**500**：落盘失败

### 13. `/model-test/list` — 历史报告列表 🟡

- **方法**：GET
- **200**：`{ ok, list, reportDir }`（`list[]` **含 `targets` 摘要**，故需读全文）
- **503**：未装配
- **备注**：与 `/test-archives` 并存，取舍见 `lib/routes.js:listRunJson` 文档

### 14. `/test-archives` — 三类档案列表 🟡

- **方法**：GET
- **200**：`{ ok, items, archiveDir }`
  - `items[]` = `{ kind, runId, size, mtime }`（**只 stat，不读内容**）
  - ⚠ **v0.9.20 变更**：字段由 `startedAt` 改为 **`mtime`**（原值是文件 mtime，名实不符）
- **503**：档案目录不可用

### 15. `/test-archives/detail` — 档案详情 🟡

- **方法**：GET
- **参数**：`?kind=<model-test|loadtest|probe>&runId=<id>`（均必填）
- **200**：`{ ok, kind, runId, report, markdown }`（`markdown` 仅 `model-test` 有，其余 `null`）
- **400**：kind 不在白名单 / runId 非法 / **路径越界**
- **404**：档案不存在　**503**：目录不可用

# 二、config schema 契约

**入口**：`normalizeConfig(raw)`（`lib/config.js`）· 持久化：`store`（`state.json`，`version: 1`）
**稳定性**：🟢 核心键稳定；🟡 `timeWindows` 与 `providerMeta` 扩展字段为实验

| `firstTokenTimeoutMs` | number | — | 🟢 | 首 token 看门狗超时 |

| `exhaustionWindowSec` | number | — | 🟢 | 耗尽窗口 |

## 2.2 `providerMeta[provider]` 🟡

### 用户声明字段（写入 `state.json`）

| 字段 | 类型 | 引入 | 说明 |
| --- | --- | --- | --- |
| `quotaGroup` | string | v0.8 | 配额组（同组共享配额）|
| `tier` | `'free'\|'paid-baseline'\|'unknown'` | v0.8 | 计费档 |
| `exclude` | boolean | v0.9.6 | 排除出「注册表自动展开」的候选池（**不否决**手工 route 条目与会话 seed）|
| `rpmLimit` | number | v0.9.10 | 每分钟请求数声明 |
| `tpmLimit` | number | v0.9.10 | 每分钟 token 数声明 |
| `resetPolicy` | object | v0.9.10 | 重置规则 `{window:'minute'\|'hour'\|'day'\|'rolling', at?, rollingSec?}` |
| `resetPolicySourceUrl` | string | v0.9.10 | 来源链接（供人工复核）|
| `tpmLimitSourceUrl` | string | v0.9.10 | 同上 |
| `notes` | string | v0.9.10 | 备注，**长度上限 500** |

### 服务端派生字段（**只读回显，禁止回传**）

| 字段 | 说明 |
| --- | --- |
| `observed` | 实测观测（来自 metrics）|
| `conflicts` | 声明与实测的冲突标记 |

> ⚠ **写回约束**：客户端保存时必须用 `stripDerivedMeta()` 剥离 `observed`/`conflicts`，
> 否则派生数据会被错误持久化。有测试守住。

### hop 内联覆盖（v0.9.10 / v0.9.19）

`rules[].route[].{rpmLimit,tpmLimit,resetPolicy,notes}` 与 `providerMeta` **同语义**，
**hop 内联优先于 `providerMeta`**。

## 2.3 `timeWindows` 🟡

| 字段 | 类型 | 校验 |
| --- | --- | --- |
| `enabled` | boolean | 仅 `true` 时生效 |
| `peakStart` | string `HH:MM` | 正则 `^\d{2}:\d{2}$`；**不得等于 `valleyStart`** |
| `valleyStart` | string `HH:MM` | 同上 |
| `peak.route` | array | 每项走 `checkProviderModel`（与 `rules[].route` 同强度）|
| `valley.route` | array | 同上 |

**段语义**：半开区间 `[peakStart, valleyStart)`；`peakStart > valleyStart` 视为跨零点。
判定实现：`segmentOfHHMM()`（`lib/router.js`，**router 与 routes 共用**）。

**`/status.timeWindows` 回显**：`{segment, nextBoundaryAt, peakStart, valleyStart, …}`

## 2.4 `reports` 🟢

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | boolean | `false` | 日账本 + 每日调度总开关 |
| `hour` | string `HH:MM` | `'01:00'` | 每日生成时刻 |
| `dir` | string（绝对路径）| 默认 `~/Documents/dsh-model-router-reports` | 报告目录 |
| `modelTestThreshold` | object | — | `{primary, backup}`，满足 `0<=backup<primary<=1` |

# 三、落盘格式契约

**目录**：`~/Documents/dsh-model-router-reports/`（可由 `reports.dir` 覆盖）

## 3.1 档案文件（三类）🟡

**命名**：`<runId>.<kind>.<ext>` · **kind 白名单**：`model-test` / `loadtest` / `probe`
**当前 schemaVersion**：`1`

**顶层字段**（实测自真实档案）：

| kind | 扩展名 | 顶层字段 |
| --- | --- | --- |
| `model-test` | `.json` + `.md` | `kind` `schemaVersion` `runId` `ok` `startedAt` `finishedAt` `elapsedMs` `aborted` `partial` `phases` `phaseOrder` `targets[]` |
| `loadtest` | `.json` | `kind` `schemaVersion` `runId` `startedAt` `finishedAt` `elapsedMs` `aborted` `phases` `results` |
| `probe` | `.json` | `kind` `schemaVersion` `runId` `startedAt` `finishedAt` `elapsedMs` `targetCount` `enabled` `entries` `benchmarks` |

> 实测样本：`model-test` 12 键 / `loadtest` 9 键；`probe` 实机**尚无样本**（从未落盘）。

**原子写**：`.tmp-<ts>-<rand>` → `rename`；**失败时清理 tmp**（v0.9.20 修复）

**向后兼容**：**v0.9.9 之前**的旧档案形如
`{ok, runId, startedAt, finishedAt, aborted, partial, targets}`（**无** `kind`/`schemaVersion`/
`elapsedMs`/`phases`/`phaseOrder`）→ 读取端按 `model-test` 处理
（`kindOfFilename` 返回 `null` 时兜底）。实机存在此类旧档案。

**runId 安全**：正则 `^[\w.-]+$`，长度 ≤ 200，**显式拒绝 `..`**；读取侧另有「路径前缀确认」第二道防线

## 3.2 日账本 NDJSON 🟢

**文件**：`<YYYY-MM-DD>.ndjson`（每日一行一记录，append-only）
**写入方式**：`JSON.stringify({ day, ts, ...rec })` —— **`undefined` 字段被省略**，
故**字段集随记录类型变化**（实测 169 条出现 **3 种组合**）。

**必现字段**（实测 136/169 条的基线组合）：
`day` `ts` `provider` `model` `outcome` `inSequence` `seqId` `attemptIndex`
`attemptsTotal` `switched` `e2eMs` `sessionId` `tokens`

**条件字段**（按需出现）：

| 字段 | 出现条件 | 实测条数 |
| --- | --- | --- |
| `errorCode` | 仅 `outcome === 'failed'` | 30/169 |
| `ttftMs` | 有首 token 计时时 | 3/169 |

**⚠ 不在此处**（易误解）：`segment` / `prevProvider` / `prevModel` **不写入 ndjson** ——
它们只进 `metrics` 内存环形缓冲（驱动「诊断 → 切换明细」页签）。
实测 169 条记录中 **0 条**含这些字段。

**`outcome` 取值**：`committed` / `failed` / `aborted`
**`tokens` 结构**：`{inputTokens, outputTokens, cacheReadTokens}`

## 3.3 每日报告 🟢

**文件**：`<YYYY-MM-DD>.report.md`（Markdown，原子写）

## 3.4 配置态 🟢

**文件**：`state.json`（`storePath`）

```json
{ "version": 1, "rules": [], "timeZone": "...", "mode": "...", "savedAt": "<ISO>" }
```

> ⚠ **v1.0 已知缺口**：`version !== 1` 时当前实现是**整份忽略**（`lib/store.js:15`），
> 而非迁移。**迁移链为 v1.0 待办项 #2**。
