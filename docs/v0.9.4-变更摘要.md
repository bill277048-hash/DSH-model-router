## 一、本次变更清单

### 1. ISS-01 根治 · store 加载点剥离残留 match（漏洞 1，A-3）
- 技术根因（v0.9.3 装配事实）：store 存在时 `index.js` 用 `cfg.rules = stored.rules` 整体替换规则，**绕过 normalizeConfig 的 match 丢弃**——仅改 normalizeConfig/normalizeState 无法根治。
- 修复：抽出 `stripLegacyMatch(rules, allowLegacyMatch, log)` helper（config.js 导出，`isPlainObject` 判定），store 加载点改为 `cfg.rules = stripLegacyMatch(stored.rules, cfg.allowLegacyMatch, log)`。
- 行为：patch 路径在 normalizeConfig 入口先 strip、store 路径在 index.js A-3 strip，两条路径各自独立、各 warn 一次、行为一致。

### 2. 新增 `allowLegacyMatch` 配置开关（A-1/A-2/A-5）
- 默认 `false`：`rule.match` 一律剥离（不再命中），启动日志 warning 明示；
- 显式 `true`：保留旧 v0.8 明细解析（provider/model/default/sessionIds/hours）；
- `match` 类型校验保留、开关无关 fail-fast；
- status 接口 `config` 块回显 `allowLegacyMatch`。

### 3. 漏洞 2 修复 · `normalizeState` 复用 patch 现值（A-4）
- 此前 `normalizeState` 构造 raw 不含 `allowLegacyMatch`，面板保存会把 legacy 语义强制归 `DEFAULT=false`；
- 现 `normalizeState(raw, legacyMatch)` 显式复用 patch 现值，routes.js POST /state 透传 `config.allowLegacyMatch === true`；
- S-3 定稿：默认参数仅作签名兜底（实际不可达），state 路径不传 `opts.log`（面板保存不产生 match-warning）。

### 4. 免费模型 429 调优 · free-tier 跨请求节流（B-1/B-2）
- 痛点：`requestIntervalMs` 仅在单请求内候选间生效，独立请求连发仍频繁 429；
- 修复：模块级纯函数 `throttleWait` + `interProvider` 账本（provider → 最近成功发送时刻 ms）；
  - 发起前对 `seed.provider` 只读等待；请求内相邻候选间隔与跨请求口径统一（`Math.max`）；
  - **成功路径才推进账本**（S-1：失败/中止不推进，避免「一次失败锁死 provider N 秒」）；
  - 仅 `reqIntervalMs>0` 生效（free-tier=2000ms/500ms 默认不改）；普通/其它模式零行为变化。

### 5. 上下文 400 调优 · context 码纳入 failover + 窗口感知重排（B-3/B-4/B-5 + 修正 1）
- B-3：`failoverSignals` 追加 `CONTEXT_LENGTH`/`CONTEXT_WINDOW`/`TOO_MANY_TOKENS`（累计上下文超窗 400 不再硬失败）；
- 修正 1：registry `refreshModels`/`registeredPairs` 透传 `contextWindow`（camelCase 对齐 packages-adapter.js:62）；
- B-4：`router.noteContextFail()` 打点后 60s 内 `contextReorder(chain, hint)` 把大窗口候选前移（>=hint 优先、同侧窗口降序、无窗口殿后/小干预）；收敛态 `slice(0,1)` 取到被排前的大窗口首选（O-2 子用例）；
- B-5：wrapper failover 判定命中 context 码时额外打点（判定本身不变）。

### 6. 每日报告 UX 三连修（v0.9.3 实机根因补强）
**根因**（v0.9.3 实机部署后用户反馈）：点击「立即生成昨日报告」看似无效或找不到落盘文件。
- **R-1**：`daily.readDayRecords(day)` 只读磁盘 NDJSON，**不合并内存 `_buffer`**。v0.9.3 P1-4 引入 5s/100 条异步批量写后，存在「刚 recordCall 推入 buffer、磁盘还没落盘」的窗口——`/reports?day=<今日>` 与「立即生成昨日」可能命中 no-data。
- **R-2**：`daily.generate(day)` 写盘失败**仅 log.error 即返 report 对象**——前端 `body.ok=true` 但磁盘无文件，用户「按钮变回 + 内容不变」以为是 bug。
- **R-3**：`/status` 顶层**不回显** `reports.enabled / reportDir`——用户不知报告文件落在哪。

**修复**：
- **R-1 修**：`readDayRecords(day)` 改为内存权威 + 磁盘追加事实——先吃 `_buffer[day]`（按 recordCall 引用相等性去重），再吃磁盘 NDJSON 行；`hasData` 同样受惠；
- **R-2 修**：`generate(day)` 写盘失败改为 **throw**（包装错误含 `daily report write <day> failed: <cause>`）；`POST /reports/generate` 显式 try/catch → 500 + `error: "report write failed: ..."`，避免被通用 `guard` 包成模糊的「插件内部错误」；
- **R-3 修**：`/api/model-router/status` 顶层新增 `reports: { enabled, reportDir, hour }`——`enabled=false` 时也回显（`reportDir=null`），开启后回显绝对路径（`join(dirname(storePath), 'reports')`，默认 `~/.deepseek-harness/home/reports/`）。

### 7. 每日报告启动按钮（UX 补丁）
- 痛点：用户「不知道在哪儿开启 reports.enabled」——此前只能手改 patch 文件或依赖默认配置。
- 修复：
  - `normalizeState` 新增透传 `reports` 段（未提交时不重置 patch 现值；显式提交才走规范化 + 回传）；`reports.hour` 沿用既有 HH:MM 校验；
  - `routes.js` POST `/state` 探测 reports 切换：`reportsChanged` 时响应带 `requiresReload: true` + `reloadHint`（明示需重启 dsh 让 daily 实例装配，macOS `launchctl kickstart -k gui/$(id -u)/com.deepseek.dsh` 随附）；
  - 面板「每日报告」页签未启用时显示横幅 + 「一键启用每日报告」按钮（POST `/state` 提交 `{reports:{enabled:true, hour}}`）；已启用态顶部显示 reportDir + 自动生成时刻。

### 8. 生成反馈 toast（UX 补丁）
- 痛点：v0.9.3「点击生成无提示」——错误只在按钮下方小字，用户看不到。
- 修复（client.js）：
  - 全局浮层 toast（sticky 面板底部）：生成成功显示「已生成 <day> · 调用 N 次 + 文件路径」；失败显示原因；
  - 「reports disabled」类错误自动内嵌「立即启用」按钮直达启用；
  - 3.5s（成功/警示）/ 6s（错误）自动消失；组件卸载清理计时器（防 setState on unmounted）。

- 与 v0.9.3 完全兼容：规则命名 / 纯选择驱动 / 逐规则 mode / 自定义参数 / 面板 / loadtest 确认门 / daily 记账语义均不变。
