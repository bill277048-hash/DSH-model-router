## 一、背景

### 1.1 上一版本产出（v0.9.3）
- 测试报告 41 用例 / 38 通过 / 0 失败 / 3 阻塞。
- 关键发现：ISS-01（旧 `match:{default:true}` 残留导致非选包会话被 default 规则接管）。
- ISS-01 临时处理已落地：store 清 match + 热更新 + 回归透传恢复（`passthroughs` 0→8）。

### 1.2 商汤免费模型实测痛点（B 工作流动机）
- 痛点 1：高频调用频繁触发 **429**（free-tier `requestIntervalMs` 仅在单请求内重试间生效，形同虚设）。
- 痛点 2：单模型累计上下文 >100k 触发 **400**（context 类码不在 failoverSignals，且 fallback 不按窗口选）。

### 1.3 合并原则
- 改动域不重叠：A（config/registry/store/index/routes）、B（registry/router/wrapper/modes/config）。
- 统一版本 v0.9.4，CHANGELOG 一条，单部署包 `DSH-model-router-v0.9.4-部署包.zip`。
- 回退粒度：整包回退 v0.9.3（A、B 各自代码改动粒度小，可分别 revert，但需整包重发）。

### 1.4 重审确认的两条装配事实（本版技术根因）

审阅实机 0.9.3 装配顺序与 store 持久化链路后确认：

1. **store 加载整体替换 cfg.rules 且不再走 match 清理**（index.js:80-87）。这是 ISS-01「store 清理只是表象」的**真正技术根源**——不是保存时被吞，而是**启动加载时根本没跑 match 丢弃**。
2. **`normalizeState` 用不含 allowLegacyMatch 的 raw 重建规则**（config.js:565）→ 面板保存会把 `c.allowLegacyMatch` 归 DEFAULT=false。**触发条件（O-1 补充）**：POST /state body 里 rules 带 match 字段时才触发（panel 0.9.1+ 不提交 match，正常 UI 不触发；仅手写 body / 旧脚本 / 第三方迁移工具会）。

本稿据此新增漏洞 1、漏洞 2 两个修复（见 §三 A），这是 v3.0 相对 v2.0 的核心差异。

### 3.1 工作流 A —— ISS-01 match 收紧密 + allowLegacyMatch（含漏洞 1、2 修复）

**A-1 `lib/config.js` —— `isPlainObject` 导出 + `stripLegacyMatch` helper**

现有 `isPlainObject` 是文件内 function（config.js:125-127，**未 export**）。A-2 的 store 加载点需要它与相同的 match-丢弃逻辑。新增导出与可复用 helper：

```js
export function isPlainObject(v) {
  return v !== null && typeof v === 'object' && !Array.isArray(v);
}

/**
 * v0.9.4（漏洞 1 修复）：剥离旧 v0.8 的 rule.match 字段。
 * allowLegacyMatch=true 时原样保留（向后兼容）；false 时复制 rules 并剔除 match。
 * @param {object[]} rules 原始规则数组（store/patch 路径共用）
 * @param {boolean} allowLegacyMatch
 * @param {object} [log]
 * @returns {object[]} 处理后的规则数组（isPlainObject 判定 match）
 */
export function stripLegacyMatch(rules, allowLegacyMatch, log) {
  if (!Array.isArray(rules)) return rules;
  if (allowLegacyMatch) return rules; // 显式开启：保留旧语义
  return rules.map((r) => {
    if (!isPlainObject(r) || !isPlainObject(r.match)) return r;
    log?.warn?.(
      `model-router 配置警告：规则 "${(r.name ?? '<unnamed>')}" 的 match 字段已废弃；` +
      `allowLegacyMatch=false，match 已丢弃（不会命中）。` +
      `需保留旧 v0.8 语义请在顶层设 allowLegacyMatch:true。`,
    );
    const { match, ...rest } = r; // 剥离 match
    return rest;
  });
}
```

**A-2 `lib/config.js` —— `normalizeConfig` 走 `stripLegacyMatch`（M-1 已定稿调用点，决策 7）**

将现有 match 解析段（config.js:334-371）收紧密。**调用点定稿为入口统一 strip（决策 7，选审核报告 M-1 推荐选项 a）**：

- 签名 `(raw, opts = {})`，`const log = opts.log;`
- `merged` 追加 `allowLegacyMatch: c.allowLegacyMatch === true,`
- **入口先 strip**：`const rules = stripLegacyMatch(c.rules, merged.allowLegacyMatch, log);` 后再进入每个 rule 的循环处理。**约定**：
  - `allowLegacyMatch=false` → 入口统一 strip 掉所有 match，循环内不会再有 match（除非 strip 后仍出现，理论不触发）；
  - `allowLegacyMatch=true` → stripLegacyMatch 原样返回，循环内走原明细解析（保留 provider/model/default/sessionIds/hours）。
- match 类型校验保留（`rule.match 若提供须为对象`，开关无关 fail-fast）——放**入口 strip 之后、循环内**，作为变量名命中但类型非法的兜底校验。
- **一致性与防双重 warn**：store 路径（index.js:A-3）与 patch 路径（此处入口）各 strip **一次**、各自独立 warn，不重叠、不重复。

```js
// v0.9.4（漏洞 1/2 修复）：match 收紧密
if (rule.match !== undefined && !isPlainObject(rule.match)) {
  throw new Error(`model-router 配置错误：rules[${i}].match 若提供须为对象`); // 开关无关 fail-fast
}
if (merged.allowLegacyMatch) {
  // 显式开启兼容：保留旧 v0.8 明细解析（provider/model/default/sessionIds/hours 赋值段）
  const m = rule.match;
  if (isPlainObject(m)) {
    const match = { provider: …, model: …, default: m.default === true };
    /* …sessionIds/hours 校验与赋值段保持不变… */
    entry.match = match;
  }
}
// else：默认丢弃——由 store/patch 统一经 stripLegacyMatch 处理后，此处不复写 entry.match
```

```js
  if (!isPlainObject(raw)) throw new Error('model-router：state 须为对象');
  const normalized = normalizeConfig({
    propose: raw.propose === true,
    rules: raw.rules ?? [],
    fallbackPolicy: DEFAULT_CONFIG.fallbackPolicy,

    // 把 legacy 语义强制归 false（此前构造 raw 会落 DEFAULT=false）。
    allowLegacyMatch: legacyMatch === true,
  });
  …

```

```js
// routes.js：POST /state 传 patch 现值
```

> 说明(S-3 定稿)：此修复不传 `opts.log` 给 normalizeConfig（state 路径不产生 match-warning，避免面板保存误报），靠 `legacyMatch` 显式复用 patch 值。**`legacyMatch=false` 默认参数实际不可达**——routes.js 总透传 `config.allowLegacyMatch === true`，默认值仅作函数签名兜底；仅在独立调用（如单测显式调用 normalizeState(body) 不传第二参）时才依赖默认 false。注释已明示。

```js
noteContextFail() { this._lastContextFailAt = Date.now(); }

contextReorder(chain, contextSizeHint = Infinity) {
  const recent = this._lastContextFailAt && Date.now() - this._lastContextFailAt < 60_000;
  if (!recent || !Array.isArray(chain) || chain.length <= 1) return chain;
  const hint = typeof contextSizeHint === 'number' && contextSizeHint > 0 ? contextSizeHint : Infinity;
  return [...chain].sort((a, b) => {
    const wa = typeof a.contextWindow === 'number' ? a.contextWindow : NaN;
    const wb = typeof b.contextWindow === 'number' ? b.contextWindow : NaN;
    if (Number.isNaN(wa) && Number.isNaN(wb)) return 0;
    if (Number.isNaN(wa)) return 1;
    if (Number.isNaN(wb)) return -1;
    if (wa >= hint && wb < hint) return -1;
    if (wb >= hint && wa < hint) return 1;
    return wb - wa;
  });
}
```
