## 1. 概述

v0.9.9 已收口「测试档案」（一次跑批的结果文件）。
v0.9.10 转入方向性方案 v1.3 §6-A 阶段 A 的剩余部分：

- **渠道档案 schema 一次到位**（declared / observed / conflicts 三层结构）
- **声明通道扩能**（`providerMeta` 从「quotaGroup + tier」扩到承载限额 / 重置 / TPM / 来源）

**OQ1 决策影响**：采用**「声明优先，实测仅作提示」**（方案 A 变体）——

- schema **不需要** `observedOverride` / `conflictResolution` 这类复杂字段
- 路由决策**直接读声明**，**不读实测**
- 实测只用来**显示差异警告徽章**，**不进存储决策**
- 故 `schemaVersion: 1` 可保持稳定（不再升 schemaVersion）

## 2. 范围与拆分

## 3. 架构决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | **声明优先**：路由决策读 `declared`，**永远不读** `observed` | OQ1 用户决策（方案 A 变体）；天然避开"实测不可靠"反复改 schema 的 v1.2→v1.3 教训 |
| D2 | **三层结构**：`declared`（用户填）/ `observed`（自动推算）/ `conflicts`（派生，仅显示） | 方向性方案 v1.3 §4.8 三层模型 |
| D3 | `observed` **不冻结**（每次跑批/探测更新），`declared` **冻结**（setState-style：变更需 `__rev++`） | 区分"用户意图"与"运行时观测"；声明变更需显式 ack |
| D4 | **不引入 schemaVersion 递增**（OQ1 决策红利） | D1 让 schema 稳定，迁移成本 → 0 |
| D5 | **不引入"采纳实测"按钮**（Q3 默认 = 不要） | 与 D1 一致（声明优先则不需要该按钮） |
| D6 | 警告徽章阈值：`observed.tpm < declared.tpm * 0.8` 或 `observed.rpmLimit < declared.rpm * 0.8` | 经验阈值（v1.1 再调），避免偶发错误触发假警告 |
| D7 | **`__rev` 不进 store 文件**（运行时字段，只在内存） | 持久化只存用户意图，避免回放时假性冲突 |
| D8 | `conflicts` 字段**每次 GET /status 实时计算**（不持久化） | 一致性保证，避免"声明更新后忘了重算 conflicts"的同步问题 |
| D9 | **新增 store 白名单字段 4 个**：`resetPolicy` / `tpmLimit` / `tpmSourceUrl` / `notes`；旧的 `quotaGroup`/`tier` 保留 | 既有契约不退化 |
| D10 | **不读 archive.js**（v0.9.9 的档案模块与本任务无关——两个"档案"语义不同） | Enforce Simplicity（避免误用） |

## 4. 字段映射（核心：本节定，下游全依赖）

### 4.1 `providerMeta[provider]` 完整字段（v0.9.10）

**v1.1 复核修正**：`quotaGroup`/`tier` 之外，**实测发现还有 3 个既有字段**（v0.9.5 / v0.9.6 引入）：

- `quotaWindows`（v0.9.5）—— 静态声明窗口（5h/1周 等）
- `customWindows`（v0.9.5）—— 自定义窗口
- `exclude`（v0.9.6）—— 是否排除自动展开候选池

```ts
providerMeta[provider] = {
  // ── 既有字段（保持兼容，不破坏 v0.9.9 既有用户）──
  quotaGroup?: string,                  // 配额组名（v0.8.0 A-2）
  tier?: 'free' | 'paid-baseline' | 'unknown',  // 计费档（v0.8.0 A-2）
  quotaWindows?: object,                // 静态声明窗口（v0.9.5）
  customWindows?: object,               // 自定义窗口（v0.9.5）
  exclude?: boolean,                    // 排除自动展开（v0.9.6）

  // ── 新增 v0.9.10 ── 用户声明（declared）
  rpmLimit?: number,                    // RPM 上限（每分钟请求数）；null = 未声明
  tpmLimit?: number,                    // TPM 上限（每分钟 token 数）；null = 未声明
  resetPolicy?: {                       // 限额重置规则（声明）
    window: 'minute' | 'hour' | 'day' | 'rolling',
    at?: string,                        // HH:MM（window=hour/day 时有效）；'02:00' 每日 02:00 重置
    rollingSec?: number,                // 滚动窗口秒（window=rolling 时有效）；例如 60 = 1 分钟滑动
  },
  resetPolicySourceUrl?: string,        // 重置规则的官方来源（URL，可空）
  tpmLimitSourceUrl?: string,           // TPM 上限的官方来源（URL，可空）
  notes?: string,                       // 用户备注（任意文本）

  // ── 运行时字段（**不持久化**，重启重置）──
  __rev: number,                        // 声明修订号（变更 +1；用于审计/冲突呈现）
  __declaredAt: string,                 // ISO 时间戳；声明最后变更时间

  // ── 实测（observed，**不冻结**，每次探测/跑批更新）──
  observed?: {
    lastUpdatedAt: string,              // ISO 时间戳
    // 触发的 429 计数（按类型，方向性方案 v1.3 §4.7 三类）
    rateLimited429Count?: number,       // 429001 (TPM/RPM 速率限制)
    quotaExhausted429Count?: number,    // quota_exceeded_error (配额耗尽)
    accountTpm429Count?: number,        // ModelAccountTpmRateLimitExceeded (账号级)
    // 实际触发的限速档（基于近期错误反推，仅供参考；不进路由决策）
    estimatedRpm?: number,
    estimatedTpm?: number,
    sampleSize?: number,                // 采样次数（用于显示可信度）
  },

  // ── conflicts（**GET /status 实时计算**，不存）──
  conflicts?: Array<{
    field: string,                      // 冲突字段名，如 'tpmLimit'
    declared: number | object,          // 声明值
    observed: number | object,          // 实测值
    severity: 'info' | 'warn' | 'critical',
    message: string,                    // 人类可读说明
  }>,
}
```

### 4.2 字段分类矩阵

| 字段 | 类型 | 来源 | 持久化 | 进路由决策 | 进 /status |
| --- | --- | --- | --- | --- | --- |
| `quotaGroup` | 声明 | 用户/旧 store | ✓ | ✓（route hop 优先） | ✓ |
| `tier` | 声明 | 用户/旧 store | ✓ | ✓ | ✓ |
| **`rpmLimit`** | 声明 | 用户 | ✓ | **✓（v0.9.10 起）** | ✓ |
| **`tpmLimit`** | 声明 | 用户 | ✓ | **✓** | ✓ |
| **`resetPolicy`** | 声明 | 用户 | ✓ | **✓** | ✓ |
| `resetPolicySourceUrl` | 声明 | 用户 | ✓ | ✗（仅显示） | ✓ |
| `tpmLimitSourceUrl` | 声明 | 用户 | ✓ | ✗ | ✓ |
| `notes` | 声明 | 用户 | ✓ | ✗ | ✓ |
| `__rev` | 运行时 | 自动 | **✗**（重启重置） | ✗ | ✗ |
| `__declaredAt` | 运行时 | 自动 | **✗** | ✗ | ✓ |
| `observed.*` | 实测 | probe / 跑批 | ✓（快照） | **✗**（OQ1 决策） | ✓ |
| `conflicts` | 派生 | 实时计算 | **✗**（GET 时计算） | ✗ | ✓ |

### 4.3 字段优先级（避免歧义）

`providerMeta[provider]` 与 route hop 内联字段的优先级沿用既有 v0.8.0 A-2：

```
route hop 内联字段（route[].rpmLimit/tpmLimit）> providerMeta[provider] > 未声明（null）
```

**v0.9.10 新增规则**：route hop 内联也允许传 `rpmLimit` / `tpmLimit`（与既有 `quotaGroup`/`tier` 一致）。

### 5.2 v0.9.10 新增契约（纯加，不破坏）

| 契约 | 变更 |
| --- | --- |
| `GET /status` | `providerMeta[provider]` 字段扩展（rpmLimit/tpmLimit/resetPolicy 等）；新增 `conflicts` 派生字段 |

### 5.3 校验规则（POST /state）

| 字段 | 校验 |
| --- | --- |
| `rpmLimit` | 须为正整数或 null；超出 10000 警告（提示"是不是填错单位了"） |
| `tpmLimit` | 同上 |
| `resetPolicy.window` | 须为 `'minute' \| 'hour' \| 'day' \| 'rolling'` 之一 |
| `resetPolicy.at` | window=hour/day 时须为 HH:MM 字符串 |
| `resetPolicy.rollingSec` | window=rolling 时须为正整数（1-86400） |
| `resetPolicySourceUrl` / `tpmLimitSourceUrl` | 须为 http(s):// 开头（其他 → 400） |
| `notes` | 长度上限 500 字符（防 DoS） |

## 6. 冲突呈现规则

**只在差异显著时显示警告**（避免假阳性）：

| 字段 | 阈值 | 严重性 |
| --- | --- | --- |
| `tpmLimit` | `observed.estimatedTpm < declared.tpmLimit * 0.8`（实测比声明紧 ≥20%） | **warn** |
| `rpmLimit` | 同上 | **warn** |
| 任意声明字段 | `observed.sampleSize < 10`（采样不足） | info（静默提示） |
| 任意声明字段 | `declared` 设置后又清空 | info（提示清空原因） |

**冲突显示位置**：
- `/status` 的 `conflicts` 字段（前端消费）
- 面板的「可切换模型」页签 → 每渠道的「档案」入口
- **不**显示在路由日志（避免噪音）

## 8. 路由消费（Task 2）

### 8.1 节流判定（v0.9.10 新增）

```
// lib/router.js 或 lib/cooldown.js
const declared = config.providerMeta[provider] ?? null;
const rpm = declared?.rpmLimit ?? null;     // null = 未声明（不节流）
const tpm = declared?.tpmLimit ?? null;
const resetAt = computeResetAt(declared?.resetPolicy);  // 下次重置时间

if (rpm && recentRpmCount > rpm * 0.9) {
  return /* 跳过此 provider，进入下一个候选 */;
}
if (tpm && recentTpmCount > tpm * 0.9) {
  return /* 跳过 */;
}
```

**注意**：节流判定用**近期实测计数**（最近 N 秒），但**触发条件是声明的限额**（OQ1 决策红利）。

### 8.2 与既有 cooldown 的关系

- 既有 `cooldown` 记录「**连续失败次数**」（v0.8 实施）
- 新增节流判定记录「**近期请求计数**」（独立维度）
- **两者并列存在**，**不**互相替代（方向性方案 §4.7 决策）

## 9. 迁移路径

**v1.1 复核修正**：Task 7 "迁移路径" **不需要单独的任务**——`lib/store.js:11` 的 `loadState`
**只校验** `version === 1 && Array.isArray(raw.rules)`，**根本不解析 `providerMeta` 内容**，
原样透传给 `normalizeConfig` 接管校验。**D4 决策（不升 schemaVersion）的红利已在此处兑现**：

- 旧 store 文件 → `loadState` 加载 → `providerMeta` 字段原样保留
- `normalizeConfig` 看到旧字段（quotaGroup/tier/quotaWindows/customWindows/exclude）→ 既有校验通过
- `normalizeConfig` 看到新字段缺失 → `entry` 不含新键（undefined，路由不节流）

**换言之：v0.9.10 的迁移路径 =「什么都不做」**。Task 7 合并到 Task 1（schema 校验）的单测里。

### 9.1 兼容性测试（合并到 Task 1 的单测）

- 读 v0.9.9 写的 store 文件（无新字段）→ 不报错
- POST /state 不带新字段 → 不报错（旧白名单行为）
- POST /state 带新字段 → 写入新字段（旧字段保留）
- 旧 store 文件的 `providerMeta[key]` 在 /status 回显时**不出现**新字段（undefined → JSON.stringify 不输出）

## 10. 测试策略

### 10.1 单测（约 +15 条）

| 组 | 用例 |
| --- | --- |
| schema 校验 | 合法通过；`rpmLimit` 非正 → 400；`resetPolicy.at='9:00'` → 400；URL 不以 http(s) 开头 → 400；`notes` 过长 → 400 |

| 路由节流 | `recentRpmCount > rpmLimit * 0.9` → 跳过该 provider；null 声明 → 不节流 |
| 迁移 | 读旧 store（无新字段）→ 不报错；POST 新字段 → 写入 |
| XSS 边界 | 备注含 `<script>` → 不解析（源码断言无 innerHTML） |

| 突变 | 应变红 |
| --- | --- |
| `normalizeProviderMeta` 不校验 `rpmLimit` 非正 | 1 条 |
| 路由节流用 `observed` 而非 `declared` | 1 条 |
| 冲突阈值改回 `1.0`（永远触发） | 2 条 |

- /status 回显含新字段 + conflicts（合法 / 非法 / 缺字段三种状态）

- 重启后 `__rev` 重置（验证运行时字段不持久化）

## 11. 风险与缓解
